# Phishing URL and Email Detector

A small machine-learning tool that looks at a **link** or an **email** and says *Likely safe*, *Suspicious* or *Likely phishing*, with a probability and **plain-English reasons**. Includes a simple web page to test links.

**Cost: ₹0.** Python + scikit-learn + Flask. No paid APIs. It **never visits** the link: it only analyses the text, so testing is safe.

## How it works

```
 URL  ->  url_features.py  -> 29 numbers (length, IP host, '@' trick, look-alike brand,
                              suspicious TLD, keywords, entropy ...)  -> ML model (RF / GB / LR)
 Email -> email_features.py -> subject + body text -> TF-IDF + Logistic Regression
                             -> headers (Reply-To mismatch, brand in sender name, SPF/DKIM/DMARC)
                             -> every link inside is also scored by the URL model
 predict.py -> combines everything -> verdict + reasons -> app.py (web page + API) / predict_cli.py
```

Hybrid design (good interview point): **ML** gives the score, **rules** give explanations and cover cases where data is thin (the `@` trick, an allowlist of official domains).

## Folder structure
```
app.py                 web page + JSON API (Flask)
predict_cli.py         command line checker
make_data.py           creates synthetic practice data
train_url.py           trains + compares 3 URL models
train_email.py         trains + compares 2 email models
detector/config.py     brands, TLD lists, thresholds, official domains  <- edit this
detector/url_features.py, email_features.py, predict.py
templates/index.html   the web page
tests/test_sanity.py   quick tests
data/  model/          created by the steps below
```

## Step-by-step guide

### Step 1 - Install (10 min)
Install Python 3.10+ and VS Code. In this folder:
```bash
python -m venv venv
venv\Scripts\activate           # Windows
source venv/bin/activate        # Linux / Mac
pip install -r requirements.txt
```

### Step 2 - Create practice data (1 min)
```bash
python make_data.py
```
Creates `data/urls.csv` (url,label) and `data/emails.csv` (subject,body,label). Label 1 = phishing, 0 = legitimate.
This data is **synthetic** (generated by code) so you can start without any download. See Step 8 for real data.

### Step 3 - Train the URL model
```bash
python train_url.py
```
You get a table comparing Logistic Regression, Random Forest and Gradient Boosting:

| Column | Meaning |
|---|---|
| precision | Of the links flagged as phishing, how many really were |
| recall | Of all real phishing links, how many we caught |
| FP | Safe links wrongly flagged (annoys users) |
| FN | Phishing links we missed (dangerous) |

The best model by F1 is saved to `model/url_model.joblib`. Take a screenshot for your report.
The data is split **by domain**, so the same website never appears in both training and testing. This prevents "memorizing" and is worth mentioning in interviews.

### Step 4 - Train the email model
```bash
python train_email.py
```
It prints the words that push an email toward phishing or legit. This is your explainability story.

### Step 5 - Run the tests
```bash
python tests/test_sanity.py
```

### Step 6 - Try the command line
```bash
python predict_cli.py url "http://paypa1.com.secure-login-verify.tk/signin.php"
python predict_cli.py url "https://github.com/python/cpython"
python predict_cli.py email sample.eml
```
(Save any email as `.eml` from Gmail/Outlook: "Download message" / "Save as".)

### Step 7 - Start the web page
```bash
python app.py
```
Open http://127.0.0.1:5000

- Tab **Check a URL**: paste a link, press Enter.
- Tab **Check an email**: paste the whole email (with headers if possible) or load a `.eml` file.

Safe things to try (they are only text, nothing is opened):
`http://paypal.com@evil.tk/login`, `https://microsoft.com/login`, `http://185.23.44.12/paypal/login.php`, `https://bit.ly/3xYz9Qa`

The page also has a JSON API: `POST /api/url {"url": "..."}` and `POST /api/email {"text": "..."}`.

### Step 8 - Retrain on REAL data (most important for a good resume)
Synthetic data only proves the pipeline works. Before you quote any number, train on real data.

**Where to get it** (free; check each site's current terms and availability):
- Phishing URLs: OpenPhish community feed, PhishTank, or Kaggle phishing-URL datasets.
- Legitimate URLs: the Tranco top-sites list (tranco-list.eu) or Kaggle datasets with benign URLs.
- Emails: SpamAssassin public corpus and Nazario phishing corpus (older, so wording differs from today's attacks).

**Format:** a CSV with columns `url,label` (1 = phishing) and, for emails, `text,label`.
```bash
python train_url.py   --csv data/real_urls.csv
python train_email.py --csv data/real_emails.csv
```

**Two traps to avoid (great interview material):**
1. *Path bias.* Tranco contains only domains (no paths), while phishing feeds contain full URLs. The model then learns "has a path = phishing". Fix: strip paths from both classes, or collect benign URLs with paths.
2. *Safety.* Phishing feed URLs can still be live. Treat them as text only. Never open them, and never run a crawler on them from your main machine.

Also keep your **official domain** list in `detector/config.py` up to date, or load the Tranco top 10,000 as the allowlist.

### Step 9 - Tune the thresholds
Open `detector/config.py`:
- `PHISHING_AT = 0.65`, `SUSPICIOUS_AT = 0.35`.
- Lower them to catch more phishing (fewer FN, more FP). Raise them for fewer false alarms.
In security, missing phishing (FN) usually costs more than a false alarm, so explain which you chose and why.

### Step 10 - Polish for your resume
- Put it on GitHub with screenshots, the results table, and a "Limitations" section.
- Optional upgrades: a browser extension that calls the local API; Google Safe Browsing or VirusTotal lookups (free keys, rate-limited, check current limits); WHOIS domain age as a feature; a feedback button that saves wrong predictions for retraining.

## Be honest about the results
- The default numbers (roughly 91% F1 on URLs and 97% on emails) are on **synthetic data** with 3% deliberately wrong labels. They are **not** real-world accuracy. Real performance will differ, usually lower on new attacks.
- Known limits: a legitimate domain can host phishing (user-content pages, compromised sites); HTTPS is no longer a trust signal; brand-new domains and clever look-alikes can slip through; the tool does not read the web page itself.
- It gives an estimate, not proof. The wording "Likely safe" is deliberate. It never says "safe".

## Interview questions to prepare
1. **Why precision and recall, not accuracy?** Classes can be imbalanced, and a missed phishing email costs more than a false alarm.
2. **How do you know the model is not memorizing?** Domain-grouped split; test on a different dataset.
3. **Why a hybrid of rules and ML?** Explainability, and rules cover rare attacks the data barely contains (for example the `@` trick).
4. **How can attackers beat it?** Clean-looking domains, compromised legitimate sites, HTTPS, shorteners, text in images. Mitigation: add reputation feeds, domain age, page content analysis.
5. **Why Logistic Regression for email?** Its weights show which words drove the decision.
6. **What would you improve with more time?** Real data, domain age, content/visual analysis, active learning from user feedback.

## Troubleshooting
| Problem | Fix |
|---|---|
| `ModuleNotFoundError` | Activate the venv, then `pip install -r requirements.txt` |
| `FileNotFoundError: data/urls.csv` | Run `python make_data.py` first |
| Web page says results use "rules only" | Run Steps 3 and 4 to train the models |
| Real genuine login pages flagged | Add their domain to `OFFICIAL_DOMAINS` in `detector/config.py`, and retrain with more benign login URLs |
| Port 5000 already in use | Change the port in the last line of `app.py` |

## Legal and ethical note
Use this only for learning and defence. Do not test it by sending phishing messages to real people, and do not visit live phishing URLs from your main computer.
